1 什么是大模型

先分清三个词：AI、大模型、Agent。
AI（人工智能）是一个大的范围。只要机器能表现出智能行为，比如识别图片、听懂语音、翻译句子、下棋、推荐内容，都属于 AI。
大模型是 AI 里很重要的一类模型。它通过大量数据训练，学到语言、图像、代码和知识中的规律。它的特点是通用：同一个模型可以写作文、做总结、翻译、看图、写代码。
Agent不是另一个大模型，而是一种使用大模型的方式。大模型负责理解和生成；Agent 在它旁边接上工具、记忆和执行流程，让 AI 不只是回答问题，还能一步步完成任务。
可以这样理解：
●
大模型是“大脑”，负责思考和表达。
●
工具是“手和工具箱”，负责查资料、读文件、算数据、画图。
●
Agent 是“数字助理”，把大脑、工具和流程组织起来，把任务做完。
所以，前言里会安装 Python 的 Agent，核心仍然是大模型。不同的是，它不只生成一段回答，还会调用工具、跟踪步骤，把任务继续推进。

1.1 大模型有什么不同

早期让机器做判断，最直接的方法是写规则。比如判断一封邮件是不是垃圾邮件，可以规定：出现某些词、链接很多、发件人可疑，就提高风险分数。这种方法很清晰，也容易解释。但问题是，真实世界太复杂，规则写不完。新词、新写法、新例外会不断出现，规则很快就会漏掉一些情况。
后来，研究人员换了一个思路：不再手写所有规则，而是让模型从大量样例中自己找规律。模型看过很多垃圾邮件和正常邮件后，会逐渐学到哪些表达更可疑，哪些表达更正常。
再往后，模型能处理的内容越来越多：图片、语音、长文本、代码都可以进入模型。但很长一段时间里，很多系统仍然是“一个任务配一个模型”：翻译有翻译模型，识别有识别模型，换一个任务，往往就要重新准备数据、重新训练或重新调系统。
大模型带来的关键变化是：同一个模型可以处理很多任务。它不再只是一个专门工具，而更像一个通用助手。你给它不同任务，它会调用已经学到的语言、知识和模式来处理。
﻿
﻿
如果用学习做类比，传统规则系统像只背固定题型：题目稍微换个问法，就可能答不上来。大模型更像见过很多题、读过很多材料的学生，它不只是记住某一道题，而是能把学过的方法迁移到新问题上。

1.3 大模型的特点

“大”不只是说文件很大，也不只是说计算机很贵。它主要体现在三个方面：
●
参数规模大：参数可以先理解成模型内部用来保存规律的“旋钮”。参数越多，模型可以表达的模式越复杂。
●
训练数据多：模型需要从大量文本、代码、图片、音频等数据中学习语言、知识和模式。
●
适用任务广：同一个模型可以处理问答、总结、翻译、写作、代码、多模态理解等多种任务。
但“大”并不自动等于“永远正确”。模型见过很多内容，不代表它知道最新信息；模型能生成很流畅的回答，也不代表每句话都有可靠依据。后面讲边界时，我们会专门解释这一点。

1.4 大模型、平台和应用的关系

学习大模型时，还会遇到一些产品和平台名称，比如千问、万相、百炼、千问办公。
这些产品位于如下几个层次：
●
模型负责理解和生成，比如千问、万相。
●
平台负责把模型用起来，比如体验模型、调用模型、接入知识库和工具，百炼就属于这一类。
●
应用或 Agent 工具直接面向具体任务，比如读文件、写报告、做数据分析、辅助开发。
分清这三层，后面看到新产品就不容易混：有的是模型，有的是平台，有的是面向具体工作的应用。

2.1 文字接龙：回答不是一次写完的

你和大模型对话时，会看到回答一个字、一个词地出现，而不是整段同时出现。这不只是显示效果，也接近大模型真实的生成方式。
大模型生成文字时，会先根据前面的内容预测下一个 token，再把这个 token 接到已有内容后面，继续预测下一个 token。一个回答，就是这样一步一步接出来的。
可以先把大模型生成文字理解成“高级文字接龙”。你给它一句开头，它会判断后面最可能接什么。
比如输入：
xxxxxxxxxx
1
大模型是一种
后面可能接“大规模训练的人工智能模型”，也可能接“能够处理多种任务的模型”。模型每一步都会根据前面已经出现的内容，估计下一个 token 的候选。
📍 交互体验：文字接龙﻿﻿
﻿﻿起始提示词是“大模型是一种”。每一步会出现几个候选 token 和对应概率。你选择其中一个，它会被接到句子后面，然后进入下一轮。
这里有一个细节很重要：每一步出现的不是唯一答案，而是一组候选。比如输入“今天天气”，后面可能接“好”，也可能接“不错”“怎么样”“有点冷”。模型会根据上下文估计这些候选的可能性，再继续往后生成。
这也解释了一个常见现象：同样一句话问两次，回答可能不完全一样。它不是故意变来变去，而是生成过程本来就有概率。你给的信息越清楚，模型的回答方向通常越确定；你说得越模糊，它可发挥的空间就越大。
这个过程叫自回归生成（Auto-regressive Generation），也就是一步步做文字接龙，而不是一次性写完。

2.2 token 是模型眼里的文字片段

大模型一步步生成的，不一定是你眼里的“一个字”或“一个词”，而是 token。你可以先把 token 理解成模型眼里的“文字片段”。
这能解释一个常见现象：有研究者发现一些模型数不对 “strawberry” 里有几个 “r”？这是由于这些模型看到的文字和你看到的不一样。你看到的是一个个字母，模型看到的可能是 str / aw / berry 这样的几个片段。
中文也一样。你眼里是 今 / 天 / 天 / 气 四个字，但 tokenizer 可能会把它切成 今天 / 天气 两个 token。模型处理的是这些切分后的片段，再把片段转换成数字 ID。
📍 分词体验工具：真实 Qwen tokenizer﻿﻿
﻿﻿这个工具内置了公开 Qwen tokenizer。默认输入是 今天天气真不错，我们去公园散步吧。，它会被切成 11 个 token：今天 / 天气 / 真 / 不错 / ， / 我们 / 去 / 公园 / 散步 / 吧 / 。 你也可以输入自己的句子，看看 token 数、字符数和每个 token 的边界。
这个体验想让你记住的不是某个固定切法，而是一个直觉：AI 看到的文字，和你看到的文字并不完全一样。后面讲上下文长度、计费、长文处理时，都会再次遇到 token。

2.3 注意力让模型抓住关键线索

知道模型会把文字切成 token 之后，还有一个问题：它为什么能根据前面的内容，判断下一个 token 更可能是什么？
这里用到的关键机制叫注意力。生成每个 token 时，模型会回看前面的内容，判断哪些位置更重要。看到“公园”后，模型会更容易把下一个 token 预测为“散步”；看到“散步”后，它会继续结合“我们”“去”“公园”等线索，判断后面更可能接“吧”。
📍 交互体验：注意力溯源﻿﻿
﻿﻿点击任意 token，可以看到模型在生成它时，会把注意力放到前面的那些关键线索上。右下角会显示下一 token 的候选，真实的下一列 token 通常会出现在候选中。线条越明显，表示关联越强。
所以，模型能顺着上下文生成句子，是因为它在前面的 tokens 序列之间找到了相关线索。

2.4 MoE 大模型技术的持续演进

理解 token、概率和注意力之后，你已经知道大模型怎样一步步生成回答。接下来可以看一个技术发展方向：模型越来越大，能力通常会增强，但成本、速度和资源消耗也会变成问题。
MoE（Mixture of Experts，混合专家模型）就是为了解决这个效率问题的一种思路。你可以把它理解成：模型内部准备了多组“专家”，不同专家更擅长处理不同类型的信息。每次生成时，模型先判断当前任务更需要哪些专家，然后只激活其中一部分，而不是每次都让所有参数一起参与计算。
这有点像学校里有一个“专家服务台”。语文、数学、物理、英语老师都在后台待命。学生问物理题时，系统不会叫来所有老师，而是快速判断问题类型，只请相关老师参与。对学生来说，体验像是在问一个人，回答很快；对系统来说，背后其实有多个专家在分工。MoE 的价值就在这里：让模型拥有更多知识和能力，同时只激活需要的部分，所以既更聪明，也更高效。
﻿
﻿
图中 Decoder Block 可以先理解成模型内部一层一层处理 token 的计算单元；MLP/FFN 是其中继续加工信息的一部分。MoE 的变化发生在这里：把原来固定的一块 MLP/FFN，换成多组可选择的专家。
以 Qwen3-235B-A22B为例，它的总参数量是 235B，也就是约 2350 亿；但每次推理只激活 22B，也就是约 220 亿。具有 MoE 架构的模型，通常知识容量大，单次计算更省，推理速度也更容易优化。

3 大模型怎样学会当助手

如果大模型只是一步步续写文字，它为什么能听懂“帮我总结”“翻译成英文”“按表格列出优缺点”这些要求？
答案是：训练过程不只让它学会续写，还会继续教它按人的要求回答，并把回答方式调得更稳。
﻿
﻿

3.1 预训练：先见过足够多的语言和知识

第一步是预训练。你可以把它想成让模型先大量阅读：新闻、书籍、网页、论文、代码、问答记录等。读得越广，它越熟悉语言怎么组织，知识通常怎么表达，前后文之间有什么关系。
对应到训练任务，模型会反复练习“根据前面的 token 预测下一个 token”。这个练习看起来简单，但当数据足够多、类型足够丰富时，模型会逐渐学到语言规律、常识、专业表达和代码模式。
预训练数据不是越杂越好。数据质量会直接影响模型表现：
数据情况
可能影响
数据少
知识有限，容易犯低级错误
数据多但质量低
可能学到错误、重复、偏见或无用信息
数据多且质量高
泛化能力和理解力通常更强
因此，预训练数据通常要经过清洗和治理：去重、去噪、过滤低质量内容，移除有害内容，处理个人信息，并尽量覆盖不同语言和领域。
﻿
﻿
预训练之后，模型已经见过很多知识，但它还不一定会按你的要求回答。你问一个问题，它可能更像是在续写文本，而不是判断你真正想要什么。

3.2 SFT：教模型按指令回答

第二步是 SFT（监督微调）。它解决的问题是：模型怎样从“会续写”变成“会按要求回答”。
做法是给模型看大量高质量的“指令-回答”样本。比如，用户这样问，答案应该这样写；这个场景要简洁回答，那个场景要分步骤说明；要求表格，就尽量按表格输出。
和预训练不同，SFT 更看重示范质量。样本要像真实问题，答案要可靠，格式要清楚。专业任务还需要懂专业的人参与设计和审核。
公开研究里也能看到这种思路。比如 GPQA收集的是生物、物理、化学领域专家编写的研究生级问题；PHYSICS整理了大学物理和博士资格考试级别的问题。这类数据集不等同于某个模型的 SFT 训练集，但它们说明了同一个原则：专业能力不能只靠泛泛的问答样本堆出来，高质量题目、可靠答案和专家审核都很重要。
经过 SFT，模型更像一个会听指令的助手：让它总结，它就总结；让它翻译，它就翻译；让它按表格输出，它就尽量按表格输出。

3.3 偏好对齐：让回答更符合人的期待

会按指令回答，还不等于回答得令人满意。有些回答可能太啰嗦，有些看起来很自信但依据不足，有些问题本来就不该直接回答。
偏好对齐要解决的，就是“什么样的回答更合适”。一种常见做法是 RLHF（基于人类反馈的强化学习）：让模型针对同一个问题生成多个回答，再请人比较哪个更有用、更安全、更符合事实。模型再根据这些反馈调整自己的回答方式。
也有更直接的方法，比如 DPO（直接偏好优化）。它直接利用“回答 A 比回答 B 更好”这样的偏好数据来优化模型，不单独训练“评分老师”。
无论采用哪种方案，目标都不是单纯补知识，而是让模型更会表达：该回答时回答得有帮助，该拒绝时拒绝得稳妥，该说明依据时把依据说清楚。
所以，大模型不是突然变成助手的。它先通过预训练获得语言和知识，再通过 SFT 学会按指令回应，最后通过偏好对齐调整回答方式。

4 大模型的三个常见边界

﻿
﻿
大模型能帮你起草、总结、分析，也能配合工具完成更长的任务。但它不是永远正确、永远记得住、永远知道最新情况的答案机器。最常见的边界有三个。

4.1 材料太长时，它可能顾不过来

大模型每次回答，都要先“看见”你给它的内容。问题是，它一次能看见的内容有上限。
你给它一段话、一页材料，通常没问题；但如果一次塞进几百页文档、很多轮聊天记录、多个文件，它就可能漏掉中间的细节，或者记住了前半段，却忘了后半段的约束。
处理长资料时，更稳的做法不是一股脑全丢进去，而是先拆分、先摘要、先明确要查什么。就像给同事交代任务：材料太多时，直接扔一堆文件过去，不如先告诉他重点看哪里、要找什么结论。

4.2 问最新信息时，它可能不知道

大模型学到的知识来自训练数据，而训练数据有时间范围。训练之后才发生的事情，它不一定知道。
比如你问“这个产品现在多少钱”“某个工具最新版本支持什么功能”，它可能给出一个听起来很像答案的说法，但这个说法来自旧信息，甚至只是根据旧模式推出来的。
这类问题不能只靠模型记忆。更稳的做法，是给它最新材料，或者让它通过工具去查实时信息。

4.3 文字很顺，不代表一定真实

大模型擅长生成通顺的文字，但通顺不等于真实。它有时会把没见过的内容说得像真的一样：编一个不存在的出处，补一个没有依据的数字，或者把两个相近概念混在一起。
这就是常说的幻觉。幻觉麻烦的地方，不只是会错，而是错的时候也可能很自信。你如果只看语气，很难判断它是在引用事实，还是在补全一个看起来合理的答案。
所以，重要结论不能只看它写得顺不顺。涉及数字、来源、政策、合同、财务、医学、安全等内容时，最好让它给出依据，再自己抽查关键点。
知道这些边界，不是为了少用 AI，而是为了更稳地用：短任务直接问，长资料先拆；旧知识让它查新资料；重要结论要核查来源。

 继续学习

通过前面的学习，你学习大模型的一些重要概念、大模型是如何工作的，以及大模型的部分应用场景。
使用大模型并不复杂，但是用好大模型却有很多值得学习的技巧和技术。
●
开始使用：
○
首先遇到任何问题时你都应该想到大模型，尝试思考该问题是否能借助大模型来解决。
○
你不需要一开始就设计复杂流程，只要先让它帮你做第一版，然后自己判断哪里可用、哪里需要改。
●
不断改进：
○
如果大模型能解决你的问题，但是生成内容质量上还有待提升，你可以尝试改进提问方式（提示词）。
○
如果在你的业务场景中，大模型总是在编造一些内容（幻觉），你可以考虑将检索和大模型结合起来（RAG）减少幻觉。
○
当你的任务会变得更复杂，大模型可能需要读你的资料，调用工具，你也可能需要主动介入，固化流程，检查结果。
﻿
当然，用好大模型的技巧和技术远不止这些，在接下来的章节里，我们将一起学习一些能帮助你用好大模型的技巧和技术。

课后小测验

【单选题】下面哪句话最准确地描述了大模型和 Agent 的关系？
A.
Agent 是大模型的一种参数规模
B.
大模型负责理解和生成，Agent 在此基础上接入工具、记忆和流程来完成任务
C.
大模型只能处理文字，Agent 只能处理图片
D.
Agent 会取代大模型，独立完成理解、生成和工具调用
﻿
正确答案：B
﻿
下面是对每个选项的解释：
❏
A. 错误。参数规模描述的是模型大小，不是 Agent。Agent 是一种应用方式，不是一种参数单位或模型规格。
❏
B. 正确。大模型提供理解、生成和推理能力；Agent 在此基础上接入工具、记忆和执行流程，让 AI 从“回答问题”进一步走向“完成任务”。
❏
C. 错误。大模型不只能处理文字。现在的大模型可以处理文本、图像、音频、代码等多种内容；Agent 也不只是处理图片。
❏
D. 错误。Agent 不是脱离大模型单独工作的系统。大多数 Agent 的核心仍然是大模型，只是它在大模型外接入工具、记忆和流程。
